MatMind SDLC pipeline

AI-native development lifecycle with Claude Chat, Code, and Cowork

Optimized for Claude Code session limits
Claude Chat — planning
Cowork — automation
Claude Code — implementation
Infrastructure — GitHub / Vercel
Human gate — approval
Plan
01
Feature planning
Claude Chat
Brainstorm features, define scope, architecture decisions. Output: prioritized feature list with acceptance criteria.
No session limits. Use chat for all planning to preserve Code sessions for implementation.
02
Story + prompt generation
Cowork (scheduled)
Reads feature list, generates user stories with acceptance criteria and scoped dev prompts for Claude Code. References CLAUDE.md and existing code.
Better prompts = fewer Code messages burned. CRON: on demand or weekly sprint cadence.
Build
03
Development
Claude Code
One story per session. Paste the Cowork-generated dev prompt, implement, commit. Push to dev branch when complete.
1 story = 1 session. If a story needs 2 sessions, break it down. Start each session with "Read CLAUDE.md".
04
Push to dev + preview deploy
GitHub + Vercel (auto)
Code commits to dev branch. Vercel auto-creates a preview deployment with a unique URL. Live in ~60 seconds.
Branch strategy: main = prod, dev = staging. Never push directly to main.
Test
05
Regression testing
Cowork (CRON agent)
Automated test agent runs full regression: login, chat, channels, schedule, roster, RSVP, AI responses. Outputs pass/fail report with evidence.
The session-saver. Runs independently — no Code sessions consumed. Schedule after every push or nightly.
06
Review results
Human gate
Review the Cowork test report. If bugs found, log as GitHub Issues with repro steps, expected vs actual, and severity. If clean, proceed to ship.
Automated testing catches regressions. Human review catches "this doesn't feel right." Both matter.
Fix (if needed)
07
Bug fixes
Claude Code
Work from GitHub Issues. Each bug is a focused session: read the issue, fix, push to dev. One bug per session when possible.
Paste the GitHub Issue directly into Code — it has repro steps and expected behavior. Pre-diagnosed bugs = fast fixes.
08
Retest
Cowork (on demand)
After fixes land on dev, trigger regression suite again. Verify fix works and nothing else broke. Repeat until clean.
The Code→Cowork loop: Code fixes, Cowork validates. Code stays focused on implementation, never on testing.
Loop until all tests pass
Ship
09
Approve and merge
Human gate
Create PR from dev → main. Review the diff, approve, merge. Last human checkpoint before production.
PR descriptions should summarize changes and link to stories/issues resolved.
10
Production deploy
Vercel (automatic)
Merge to main triggers production deployment. Live in ~60 seconds. Zero downtime. Automatic rollback if build fails.
If something breaks in prod, revert the merge on GitHub. Vercel auto-deploys the previous version.

Session limit strategy

0

Code sessions for planning

All planning, brainstorming, and architecture stays in Claude Chat. Unlimited usage, no sessions consumed.

0

Code sessions for testing

Cowork handles all regression testing on a CRON schedule. Code never runs tests — it only fixes pre-diagnosed bugs.

1:1

Story-to-session ratio

One story per Code session. If a story needs two sessions, it's too big — break it down before starting.

2

Human gates per cycle

Review test results (go/no-go) and approve the PR (merge to prod). You stay in control without being in the loop for every step.
