## Warnings

1. **Build blocked in sandbox** — `npm run build` fails with `Cannot find module @rollup/rollup-linux-arm64-gnu`. The `node_modules` directory was installed on macOS (arm64-darwin) and committed/synced to a Linux arm64 environment. This is an environment issue, not a code defect — Vercel builds on Linux and will install correct native binaries. Still, `node_modules` should not be in version control.

2. **`supabase/migrations/002_add_team_slug.sql` idempotent seed may silently no-op** — The seed `UPDATE teams SET slug = 'lovett' WHERE name = 'Lovett Wrestling' AND slug IS NULL` will succeed quietly even if the team row doesn't exist yet (0 rows updated). If the Supabase project is fresh and the team insert in `001` hasn't run, the Lovett team will have no slug and subdomain routing will return 404. Consider adding an assertion or running migrations in a guaranteed order via Supabase CLI.

3. **`TeamContext.jsx` network error swallowed as "Team not found"** — Any network failure (CORS, DNS, Vercel cold start timeout) reaches the `catch()` block and shows the "Team not found" screen. Users will see a misleading error. A distinct error state ("Can't reach the server — try again") would improve UX.

4. **No wildcard domain config in `vercel.json`** — Subdomain routing (`lovett.mat-mind.com`) requires a wildcard domain configured in the Vercel project dashboard. `vercel.json` alone cannot enable this. This is documented behavior but should be in `ONBOARDING.md` / `docs/qa/setup-instructions.md` as a required step.

5. **Cross-tenant teamId check in `useAuth.signIn()` runs after session is created** — The profile `team_id` check (lines 74–83 of `useAuth.js`) fetches the profile after `signInWithPassword` succeeds. If the subsequent profile fetch fails (network error, RLS misconfiguration), the user could land in the app with a mismatched team. Consider moving the cross-tenant check to a Supabase Auth hook or Edge Function trigger.

6. **`supabase/migrations/001_initial_schema.sql` seed has no slug for Lovett team** — The initial seed inserts Lovett Wrestling without a `slug` column (slug column doesn't exist in `001`; it's added by `002`). This is correct as migrations run in order, but the dev branch only ships `001` and `002` — the 17 additional migrations in `main` (knowledge base, push notifications, settings, etc.) are not present in dev and are silently absent. Any code path that hits KB, notifications, or settings tables will fail at the Supabase layer.

7. **`npm audit` reports 5 moderate vulnerabilities** — `npm audit` returned 5 moderate severity advisories. Run `npm audit fix` before next release.

8. **`api/team.js` missing `SUPABASE_SERVICE_ROLE_KEY` fallback** — If the env var is unset, the function returns `503 Server not configured`. This is correct behavior, but there is no logging to surface the config gap during deployment. A `console.error` before the 503 would make Vercel log tailing more useful.
