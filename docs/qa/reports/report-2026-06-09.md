## Failures (action required)

### MSG-01 — "Coaches Only" channel missing from UI ❌

- **Steps:** Open app → Messages tab → count visible channels
- **Expected:** 6 channels rendered (MatMind AI, Announcements, Advanced, Beginner, Tots, Coaches Only)
- **Actual:** Only 5 channels shown — Coaches Only absent
- **Evidence:** `document.body.innerText` shows `Messages / 5 channels / MatMind AI … Tots`. No "Coaches Only" entry.
- **Root cause:** `src/lib/constants.js` CHANNELS array contains only 5 entries — "Coaches Only" was never added. `CHANNEL_NAME_TO_SLUG` also missing `"Coaches Only": "coaches"` mapping. The DB seed (`001_initial_schema.sql`) correctly inserts the channel, and `MatMindPrototype.jsx` (line 120) has it, but the production constants never got it.
- **Suspected area:** `src/lib/constants.js` — CHANNELS array and CHANNEL_NAME_TO_SLUG

### ENV-01 — Serverless API functions use VITE_ env prefix without fallback ❌

- **Steps:** Code review of all api/ files
- **Expected:** Server-side functions use `process.env.SUPABASE_URL` (no VITE_ prefix)
- **Actual:** Five functions use only `process.env.VITE_SUPABASE_URL` with no `SUPABASE_URL` fallback:
  - `api/admin.js:8` — `process.env.VITE_SUPABASE_URL` only
  - `api/support.js:98` — `process.env.VITE_SUPABASE_URL` only
  - `api/notify.js:15` — `process.env.VITE_SUPABASE_URL` only (also `VITE_VAPID_PUBLIC_KEY` at line 10)
  - `api/send-email.js:15` — `process.env.VITE_SUPABASE_URL` only
  - `api/team.js:11` — `process.env.VITE_SUPABASE_URL` only
- **Impact:** If Vercel project is reconfigured with canonical `SUPABASE_URL` (correct convention), all five endpoints silently fail to connect to Supabase. `api/chat.js` and `api/ops.js` already use the correct `SUPABASE_URL || VITE_SUPABASE_URL` fallback pattern — the others should match.
- **Suspected area:** `api/admin.js`, `api/support.js`, `api/notify.js`, `api/send-email.js`, `api/team.js`

## Warnings

- **WARN-01 (BUILD-01):** `npm run build` fails in linux-arm64 sandbox with `Cannot find module @rollup/rollup-linux-arm64-gnu`. This is a rollup native binary architecture mismatch — an environment issue, not a code bug. Build succeeds on macOS (dev machine) and Vercel (x86). Flag: verify Vercel latest deploy shows `READY` state.

- **WARN-02 (DATA-01):** Roster shows duplicate athlete "DAK Kalish" at two different weights — 82 lbs and 85 lbs. Both listed under Advanced group. Likely a leftover test record. Should be cleaned from seed or Supabase data.

- **WARN-03 (PWA-01):** `public/manifest.json` does not exist as a static file — the PWA manifest is generated by vite-plugin-pwa at build time. Icon files (`icon-192.png`, `icon-512.png`) exist in `public/` ✅. Could not verify generated manifest in `dist/` because build failed in QA environment (see WARN-01). Recommend verifying manifest in Vercel deploy preview.

- **WARN-04 (notify.js):** `api/notify.js` references `process.env.VITE_VAPID_PUBLIC_KEY` (line 10) server-side. VAPID public key is not secret but using the VITE_ prefix for a server-side variable is inconsistent. Should use `VAPID_PUBLIC_KEY`.
